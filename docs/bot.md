# Пользовательские сценарии Wordhord

Бот работает в личных чатах Telegram. Интерфейс на русском языке: экраны с
inline-кнопками, короткие подписи, пагинация каталогов и длинных материалов.
Навигация редактирует текущий текстовый экран; формы принимают ответы отдельными
сообщениями. Из каждого раздела можно вернуться в главное меню.

## Запуск и администраторы

В `.env` укажите токен бота и при необходимости:

```dotenv
ADMIN_TELEGRAM_IDS=123456789,987654321
STUDY_TIME_ZONE=Europe/Moscow
```

`ADMIN_TELEGRAM_IDS` — числовые Telegram ID через запятую. Свой ID можно узнать
командой `/id`. Пустой список допустим. ID и часовой пояс проверяются при запуске.
Существующее поле `user.isAdmin` тоже даёт доступ к мастерской.
Права из переменной окружения действуют на время запуска и не записываются в БД:
удаление ID из настройки с последующим перезапуском снимает это разрешение.
Если в БД отдельно установлено `isAdmin=true`, его нужно снять отдельно.

Администратор видит обычные учебные разделы и дополнительную кнопку
«Мастерская». У обычного пользователя этой кнопки нет. Проверка прав выполняется
для каждого административного нажатия и сообщения формы; знание callback data
не даёт доступа к записи в БД. Из бота нельзя назначать себе или другим
пользователям административные права.

```sh
npm run db:migrate
npm run build
npm start
```

При запуске регистрируются команды меню Telegram:

| Команда | Действие |
| --- | --- |
| `/start`, `/menu` | Главное меню |
| `/decks` | Каталог учебных колод |
| `/study` | Повторение всех выбранных колод |
| `/grammar` | Каталог правил |
| `/stats` | Личный прогресс и дневные лимиты |
| `/help` | Объяснение обучения и оценок |
| `/cancel` | Отмена ввода или выход из тренировки |
| `/id` | Свой Telegram ID |
| `/admin` | Мастерская для администратора |

## Колоды и карточки

В каталоге есть поиск и страницы по восемь записей. Выбранные колоды отмечены
галочкой; отдельный экран «Мои колоды» показывает личную коллекцию.
Внутри колоды можно добавить её в коллекцию, посмотреть словарь или начать
тренировку. Удаление колоды из личной коллекции сохраняет FSRS-прогресс:
при повторном добавлении обучение продолжается с прежнего места.

Тренировка работает с отдельными значениями слова через существующий
`studyService`. Лицевая сторона показывает слово, транскрипцию и подсказку,
если она добавлена. Перевод и определение скрыты до нажатия «Показать ответ».
На обороте доступны определение, перевод, атрибуты и примеры этого значения,
а также четыре оценки с предварительными интервалами:
«Снова», «Трудно», «Помню», «Легко».

Оценка сохраняется только после открытия ответа. Токен сессии, ID сообщения и
версия FSRS-карточки защищают от старых и повторных нажатий. Все обновления
одного пользователя обрабатываются последовательно, включая параллельные
нажатия. Запись проходит через `reviewCard`, поэтому действуют срок повторения,
дневные квоты и атомарное сохранение прогресса с журналом.

После оценки показывается следующая доступная карточка. Если очередь пуста,
бот показывает итог, доступное время следующего повторения, когда оно есть,
и объясняет ограничение лимитами. Кнопка «Проверить ещё раз» обновляет очередь;
будущие повторения не выдаются раньше срока. Новые карточки не обходят квоты.
`STUDY_TIME_ZONE` задаёт день для квот и отображение дат; по умолчанию используется
`Europe/Moscow`.

## Грамматика

Правила и материалы отображаются в порядке `order, id`. Длинные правила разбиты
на страницы с разделами, ключевыми мыслями и примерами. Иллюстрации открываются
по одной, с кнопкой перехода к следующей и возвратом к правилу.

Пользователь может отметить правило изученным и снять отметку. Для каждого
правила доступна одна личная заметка до 2000 символов: её можно создать,
редактировать или удалить. Обработчики всегда работают с текущим внутренним
`user.id`, поэтому заметки и отметки других пользователей недоступны.
Грамматика не включается в очередь FSRS.

## Мастерская

Редактор использует существующие репозитории. Доступны создание, редактирование
и удаление всего учебного контента:

- Колода → слова → значения → примеры и атрибуты значения.
- Отдельный справочник атрибутов, с выбором атрибута кнопкой в форме.
- Правило → разделы → ключевые мысли и примеры.
- Иллюстрации правила, загружаемые как фото Telegram или HTTPS-ссылка.

Связи с родителем выбираются навигацией, вводить внутренние ID вручную не нужно.
Создание проходит по шагам с проверкой длины и типа каждого поля и отдельной
кнопкой сохранения после предпросмотра. Необязательные поля можно пропустить
или очистить. Редактирование меняет одно поле за раз. Для длинных текстов раздела
и ключевых мыслей можно отправить несколько сообщений, затем нажать «Далее».
Транскрипции со слешами принимаются как обычный текст.

Удаление требует подтверждения внутри интерфейса и объясняет последствия.
Непустую колоду удалить нельзя: действует существующее ограничение `RESTRICT`.
При удалении слова/значения исчезают связанные материалы, прогресс и журнал;
при удалении правила — материалы, отметки и личные заметки. Ошибки ограничений
показываются понятным сообщением без вывода SQL.

## Аудио

В карточке слова администратор нажимает «Загрузить / заменить аудио» и отправляет
аудио, голосовое сообщение или документ поддерживаемого формата. Поддерживаются
MP3, OGG/OGA, WAV, M4A и FLAC, до 20 МиБ. Загрузка проверяет объявленный размер
и фактическое количество скачанных байт, имеет таймаут и не следует редиректам.

Файлы сохраняются в **`audio` в корне проекта**, независимо от каталога запуска.
Имя генерируется через UUID; имя исходного файла не используется как путь.
Сначала создаётся `.part`, и только полностью загруженный файл переименовывается.
При ошибке временный файл удаляется. В `card.audioUrl` сохраняется относительный
путь вида `audio/<uuid>.mp3`; токен Telegram в БД и сообщениях не сохраняется.

Кнопка произношения работает в словаре и на обеих сторонах тренировочной карточки.
MP3/M4A отправляются как аудио, OGG/OGA — как голосовое сообщение с резервной
отправкой документа, WAV/FLAC — как документ. Существующие HTTPS-ссылки и Telegram
file ID в `audioUrl` также поддерживаются. Локальные пути ограничены папкой
`audio`; символические ссылки не используются для чтения.

При замене, удалении аудио или слова старый локальный файл удаляется, если
больше ни одно слово на него не ссылается. Файлы аудио исключены из Git;
для резервного копирования сохраняйте папку `audio` вместе с согласованной
парой SQLite-баз.

## Состояние и проверки

Профиль Telegram регистрируется автоматически при первом обращении и обновляется
при смене имени. Учебный прогресс, коллекция, заметки и отметки находятся в БД.
Состояние текущего экрана, формы и тренировки хранится в памяти до двух часов
бездействия. После перезапуска старые кнопки сохранения и оценки отклоняются;
пользователь открывает `/menu` и продолжает с сохранённым прогрессом. Незавершённый
черновик формы после перезапуска нужно заполнить заново.

`npm test` собирает проект и запускает сценарии `test/bot.test.cjs` на временных
SQLite-файлах с настоящими миграциями. Telegram API подменяется на уровне grammY;
тесты проверяют доступ, каталог, обучение, повторные нажатия, личные данные,
CRUD всех видов материалов и аудио. Рабочие базы и живой Telegram не используются.
Для финальной проверки в Telegram запустите бота со своим токеном, настройте
администратора и добавьте тестовую колоду с одним словом и значением.

Обработчики используют официальные API [inline-клавиатур grammY](https://grammy.dev/plugins/keyboard)
и [работы с файлами](https://grammy.dev/guide/files).
